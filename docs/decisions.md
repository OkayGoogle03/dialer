## Batch 2 (database switched to TiDB by user request)
D-002 now uses `database/dbctl.mjs`. D-003 (RLS), D-004 (BYPASSRLS role), D-005 and D-007 (partitioning) and D-010 (PGlite tests) are superseded by the entries below.

| ID | Decision | Reason |
|---|---|---|
| D-014 | Database = TiDB Cloud (MySQL 8 dialect) at the user's explicit choice, accepting loss of row-level security | User instruction. I recommended keeping PostgreSQL for RLS; recorded as an accepted trade-off. |
| D-015 | Isolation without RLS: (1) `withTenant` binds `:tenantId` from verified context and rejects caller-supplied values; (2) SQL guard requires one `:tenantId` bind per tenant-table reference and forbids comma joins; (3) composite `(tenant_id,id)` FKs; (4) DB-user grants; (5) test that `TENANT_TABLES` covers every table with `tenant_id` | Defence in depth replacing RLS. The guard is heuristic (counts binds); it complements review and tests rather than replacing them. |
| D-016 | Two DB users: `dialer_api` (tenant-scoped; cannot write tenants/platform_admins/audit; cannot read outbox) and `dialer_platform` (cross-tenant; only platform module, outbox relay, consumers, CLI) | Platform privilege is unreachable from tenant routes. |
| D-017 | Super admin = row in `platform_admins` (platform tenant only); JWT `pa` claim is advisory, `PlatformAdminGuard` re-reads the table per request | Instant revocation; tenant users cannot write the table. |
| D-018 | Suspension: 15 s tenant-status cache in the auth guard + refresh-token revocation + local cache invalidation | Bounded propagation without a DB hit per request; Redis broadcast later. |
| D-019 | `call_events` not partitioned on TiDB (partitioned tables cannot carry FKs; TiDB range-shards automatically); retention by TTL job in Phase 2 | Platform difference. |
| D-020 | Integration tests run on `<DB_NAME>_test` in the same TiDB cluster, unique tenant slugs per run | No Docker locally; real engine beats emulation. Slower (network). |
| D-021 | Idempotent DDL and per-statement migration tracking | TiDB DDL is not transactional. |
| D-022 | "Unique among live rows" via virtual column `live = IF(deleted_at IS NULL,1,NULL)` in unique keys | No partial indexes in MySQL. |
| D-023 | Outbox relay: lease columns, per-row exponential backoff, retry forever, `Nats-Msg-Id=event_id`; at-least-once | Several API instances can relay safely; no event loss. |
| D-024 | Consumers: `processed_events` marker and handler in one DB transaction; after `maxDeliver`, dead-letter to `DIALER_DLQ` | Exactly-once effects over at-least-once delivery. |
| D-025 | Shared packages built to CJS+ESM; API/Jest/Vite resolve them from source | No pre-build in dev. |
| D-026 | Anti-escalation: an actor may only grant, or modify holders of, permissions the actor holds | Stops user-managers minting admins. |

## Batch 3 - master data, Excel caller import, outbound routing
The spec for this batch said PostgreSQL; the project database is TiDB (D-014), so TiDB was kept.

| ID | Decision | Reason |
|---|---|---|
| D-027 | "SIP trunk" = the existing `tenant_sip_providers` table (extended in 0006); "service provider" = new `service_providers` business entity above it | Avoids a duplicate trunk table; provider = routing/priority/limits, trunk = connection + encrypted credentials. |
| D-028 | `provider_dids` is the DID master; the older `caller_ids` table (campaign FK) is left untouched | `caller_ids` has no provider link; changing it would break the campaign schema. |
| D-029 | Anything that could carry a call must be *verified*: trunk (test + admin confirm), DID (admin confirm), call server (real ARI check). Editing connection settings resets verification and deactivates. Routing refuses unverified resources | Requirement "never mark unverified provider/DID/server operational". Trunk "verified" = reachable + admin attestation; SIP registration is not proven (Phase 2). |
| D-030 | Excel import is two-phase: preview (read-only) -> approve proposals (creates Pending records, never technical config) -> confirm (re-validates with `allowProposals=false`) | Nothing is created implicitly; confirm cannot import rows whose master data was not approved. |
| D-031 | `.xlsx` only (user decision); header row checked exactly and independently of worksheet protection; template samples live on the Instructions sheet, not the data sheet | `.xls` has no maintained safe parser; samples in the data sheet would be imported by accident. |
| D-032 | Prefix = dial prefix prepended to the destination number for that assignment (+E.164 input is already international) | User had no preference; this is the common dialer meaning. DID stays the caller ID. |
| D-033 | Concurrency reservation: row locks in fixed order (provider, trunk, DID, server, process) + **locking** count read + insert, then adapter call outside the transaction; deadlock retry | TiDB plain reads use the transaction-start snapshot, so a non-locking count let 6/6 parallel calls through a limit of 2 (found by test). |
| D-034 | Uncertain call outcomes (timeout after send) are never retried and are reported as `uncertain`; only gateway failures (500/502/503/504, ARI unreachable) fail over | Avoids duplicate calls. |
| D-035 | Telephony behind `TelephonyAdapter`; `AriTelephonyAdapter` implements ARI HTTP originate/hangup but is only verified against a local stub | No Asterisk or SIP trunk available. |
| D-036 | Connectivity probes allow private ranges (Asterisk is usually internal) but refuse link-local/cloud-metadata addresses; admin-only, rate limited | SSRF mitigation without breaking the normal deployment. |
| D-037 | `caller_import:manage` (supervisor + admin) lets approval create Pending providers/processes/servers/DIDs; activating them needs `sip_providers:manage` / `call_servers:manage` | Imports can propose, only admins can make anything operational. |

## Softphone pivot (2026-11-19)
| ID | Decision | Why |
|---|---|---|
| D-038 | Calls are placed by the agent's **softphone registered with the call server (PBX)**, like X-Lite; they no longer go through trunks/providers. Provider, DID and Excel columns are kept as records but are ignored for routing. The old trunk-routing API (`/dialer/*`) is kept in the backend but has no UI | User requirement. Keeping the data avoids a destructive migration and keeps the Excel format stable. |
| D-039 | `call_servers.host/port` are the SIP address the softphone registers with; migration 0007 adds `sip_transport` (wss/ws/udp/tcp/tls), `sip_ws_path`, `sip_realm`, `address_updated_at`. The browser softphone derives `wss://host:port/path` | The PBX IP is dynamic; admin edits one field. |
| D-040 | Dynamic IP = **admin updates the address, softphones refetch it** at login, on reconnect/focus/online, every 5 min and every 30 s while unregistered; the UA restarts only when address or credentials changed and never during a live call. Changing the address never deactivates the server; activation needs only an address (ARI check is optional) | User choice. Avoids DDNS dependency; edits are routine, so they must not break the setup. |
| D-041 | **Exception to "never expose SIP credentials to the frontend":** each agent's own SIP password is returned by `GET /softphone/config` to that agent only (selected by the verified JWT user, never by request input; `Cache-Control: no-store`; audited as `softphone.config_read`). It is encrypted at rest (AES-256-GCM), write-only for admins, and an admin cannot read an agent's password through the API | A browser softphone must hold the SIP secret to REGISTER. Per-agent credentials limit the blast radius to one extension; recommended practice is a PBX-side low-privilege, rate-limited extension per agent. |
| D-042 | The **server applies the prefix**: `POST /softphone/calls` normalises the number (prefix prepend, `+`/`00` international untouched, trunk-zero strip, process dial plan) and returns the exact target the browser must dial; it also writes the `call_sessions` row and `call.created`. The client reports ringing/answered/completed/failed via `PATCH`; transitions are validated, terminal states immutable, retries idempotent | Prefix and dial-plan rules cannot be bypassed from the browser, and the call log exists even if the page closes. Client-reported status is untrusted-by-design until PBX call events (Phase 2) corroborate it. |
| D-043 | Browser softphone only supports `wss`/`ws`; `udp/tcp/tls` call servers show "unavailable" in the browser and are for the future Windows desktop app | Browsers cannot open raw SIP sockets. |
| D-044 | Windows desktop app = Electron shell around the web softphone (apps/desktop), not a native PJSIP client. Unused screens removed: SIP Providers, DIDs, provider/DID assignment, ARI/environment/limits fields on call servers, routing strategy on processes (APIs kept) | Fastest path to an installable Windows app that shares one softphone codebase and server-side prefix logic. Native UDP/TCP SIP needs a PJSIP build and is deferred; UI trimmed to what the call-server model uses. |
| D-045 | Deletes cascade where the old rule blocked users: deleting a process removes its dial prefixes; deleting a call server removes its prefixes, process links and SIP accounts; deleting an imported Excel batch removes the batch and its prefixes (master data stays); users can be soft-deleted (not yourself). Blocked only if old trunk-dialer call history references the prefixes | Users could not delete records because of "remove X first" conflicts. |
| D-046 | "Download App" page reads `DESKTOP_DOWNLOAD_URL` / `DESKTOP_VERSION` (non-secret config). The 77 MB installer is not stored in git | Needs a host for the file (e.g. a release or storage URL); until set, the page says it is not published. |
| D-047 | **Call lists** replace the Processes / Caller Excel Import screens: one Excel (Call Server IP, SIP ID, SIP ID Password, Prefix, Phone Number) for one agent. Import upserts the call server by IP (new IP => new active call server, only if the importer has `call_servers:manage`) and the agent's SIP account (one per agent per server; password encrypted, never stored in list rows, never exported), and stores every row (bad rows as `invalid` with the reason). Old process/provider/DID APIs remain | User requirement: call server, SIP account, prefix and numbers all configured dynamically from Excel. |
| D-048 | Per-row status is written server-side from the softphone's call events (calling -> ringing -> answered -> completed / not_answered / failed with SIP code) and shown live (2 s poll while a call is active, 8 s otherwise, instant refresh on each call state change); the agent can Call, Call next, or enable Auto-dial next; results export to Excel (`GET /call-lists/:id/export`) | Realtime visibility and an Excel result report. Poll, not push: no websocket/SSE infrastructure on Vercel. |
| D-049 | **Native SIP engine in the desktop app** (apps/desktop/sip/sip-ua.js, pure Node): REGISTER with digest auth, outbound/inbound calls, RTP G.711 (PCMU/PCMA) and RFC 2833 DTMF over **UDP or TCP**, running on the agent's own PC. Via/Contact/SDP carry this PC's address (learned by routing towards the call server); the destination is the call server IP/port from the Excel-created call server and the SIP ID/password from the Excel. The web softphone page uses it when `window.desktop.sip` exists and the server transport is udp/tcp; browsers keep using JsSIP for wss/ws | User's PBX accepts only normal SIP (UDP/TCP) like X-Lite. Chosen over a PJSIP build to stay buildable here; trade-off: no SRTP/TLS, no NAT traversal, G.711 only. |
| D-050 | Call servers created from an Excel call list get the transport from `DEFAULT_SIP_TRANSPORT` (config file: `udp`; code default `wss`) and the standard port (5060 udp/tcp, 8089 wss, 8088 ws); the softphone config resolves a missing port the same way | The Excel carries only the IP. |
