# Database

**Engine: TiDB Cloud (MySQL 8 dialect)** — see docs/decisions.md D-014…D-022. There is **no row-level security**; isolation is enforced by the API data layer, composite FKs and DB grants.

```bash
pnpm db:migrate        # owner credentials; idempotent, per-statement checksums
pnpm db:setup-roles    # creates dialer_api / dialer_platform and per-table grants
pnpm db:status
```

## Users
| User | Used by | Access |
|---|---|---|
| owner (`DB_OWNER_*`) | migrations, role setup, test assertions | DDL; never given to the running API |
| `dialer_api` | tenant-facing API | DML on tenant tables via `Database.withTenant`; read-only on `tenants`, `plans`, `permissions`, `platform_admins`, `subscriptions`, `invoices`; INSERT/SELECT only on audit-like tables; INSERT-only on `outbox_events` |
| `dialer_platform` | platform module, outbox relay, event consumers, provisioning CLI | cross-tenant DML; audit append-only |

## Conventions
- ids: `CHAR(36)` UUIDs generated by the application; times `DATETIME(3)` UTC.
- Tenant tables: `tenant_id NOT NULL`, `UNIQUE(tenant_id,id)`, composite FKs `(tenant_id,x_id) -> x(tenant_id,id)`.
- Soft delete + uniqueness: virtual `live` column in unique keys.
- `CHECK` is documentation only on this cluster; validate in the API.
- Statements must be idempotent (TiDB DDL is not transactional).
- New tables must be added to `TENANT_TABLES` (database.ts) and classified in `API_GRANTS` (dbctl.mjs); tests and `setup-roles` fail otherwise.
- Never run `SET GLOBAL` or touch other databases: the cluster is shared with other projects.
